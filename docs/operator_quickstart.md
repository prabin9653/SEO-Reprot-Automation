# Operator quick-start

Run everything from the project folder with `seo` (the `seo.cmd` wrapper): it finds Python and the source by itself, and the runner settings are read from
`%LOCALAPPDATA%\JasperSEOReporting\config\runner.yaml` (or pass `--config PATH`). Nothing writes production data unless the command says `--production`.

## The normal flow for one client

| Step | Command | What it does |
|---|---|---|
| 1 | `seo clients check` | One table: every client is READY, FIX (with the exact fix), NOT KEYED, SKIPPED, or registered but not in the sheet. Shows whether a report already exists on this device and whether Google is verified here. |
| 2 | `seo clients add --name "<exact sheet name>"` | Registers a sheet client in `config/clients.yaml` (a `.bak` copy is kept). The key is made from the name, for example `acme-floor-covering`. **A key is permanent once a report exists.** Use `--key` to choose it. |
| 2b | `seo clients add --all-missing` | Shows which sheet clients have no key. Add `--yes` to write them all. |
| 3 | `seo verify live --client <key> --live` | Checks Google access and stores a 7-day verification on this device. |
| 4 | `seo report run --client <key> --period <start>_<end> --production` | Builds the report. The period must equal the sheet's dates and cover exactly 28 days. |
| 5 | `seo report open --client <key>` | Opens the latest finished PDF (`--period` picks another, `--no-open` only prints the location). |

## When something goes wrong

Every error now prints **what it means** and **what to do**. The usual ones:

* `already_complete` is not a failure. A finished report is never overwritten. Open it with `report open`, change the period in the sheet, or make a labelled `report preview`.
* `auth_credentials_revoked`: run `seo setup auth`, then `verify live` again. This happens about weekly while the Google consent screen is in Testing mode.
* `gsc_property_not_accessible`: the sheet's Search Console property must match Search Console exactly (www or not, http or https, trailing slash, `sc-domain:`) and the signed-in account needs access.
* `attestation_expired` / `live_google_not_verified`: run `verify live --client <key> --live`.
* `period_differs_from_workbook`: use the exact dates from the sheet (`clients check` shows them).

Verification is stored per Windows account on each device (it is bound to that account), so every teammate verifies on their own device.

## The web page (no commands to type)

```
seo web
```

Opens a page on this computer only (127.0.0.1, port 8765, or another free port). The address printed in the terminal contains a one-time access token that
changes every time it starts. The page shows this device's Google status and a table of every client with its status, period, report and Google state, and has
buttons for **Register**, **Verify and run**, **Run report**, **Retry**, **Open PDF**, and **Run all that are ready**. A History tab lists what has been run on this
computer.

* It runs the same commands as above, so every safety check (the 28-day rule, the 7-day verification, the production gate, never overwriting a finished report)
  is unchanged. Verification is done for one client right before that client's report, because each verification replaces the previous one.
* Only one job runs at a time. A running report cannot be cancelled from the page; press Ctrl+C in the terminal that started `seo web` to stop it.
* If Google sign-in has expired, run `seo setup auth` in a terminal once, then press Refresh.
* Stop the page with Ctrl+C in its terminal.

## Setting up a new computer

See [team_setup.md](team_setup.md): install with `scripts\install_device.ps1`, then `seo setup device` creates the per-user folders, installs the report fonts, writes the
settings file and lists exactly what is still missing (the OAuth client file, the Google sign-in, the client registry).

## Who ran a report, and reports made on other computers

* Every run records **who started it**: your Windows account name, and whether it came from the console (`cli`) or the web page (`web`). The page and
  `seo clients check` show "Generated ... **by maria**", and the History tab has a "Generated by" column. The person is the one whose request actually finished the
  report; someone who only re-clicked later and got "already complete" is not shown as the author. On a shared Windows account, set the environment variable
  `JASPER_SEO_OPERATOR` to your own name first.
* Because each computer keeps its own history, a teammate cannot see your reports by default. If the team has a **shared folder** (synchronised or a network share),
  set it once (`seo setup device --shared-folder "D:\TeamShare\seo-activity"` on a new device, or add `paths.shared_activity_dir` to `runner.yaml`). Each computer then
  appends one small line per finished report (client key, period, operator, computer name, time; no paths, e-mails or credentials) to a file of its own there.
  The page and `clients check` then warn: **"Already generated by Bob on another computer (LAPTOP-2) ... Running it here makes a second copy."**
* It is a **warning, not a lock**: computers that cannot talk to each other cannot prevent two people from running the same client, so the page asks you to confirm.
